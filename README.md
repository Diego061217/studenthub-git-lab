# StudentHub

StudentHub es una plataforma para gestionar servicios académicos universitarios.

## Funcionalidades

- Gestión de estudiantes
- Gestión de cursos

## Equipo

- Developer A
- Developer B

## Reglas del Equipo

1. **Ramas independientes:** Cada tarea se trabaja en su propia rama (`docs/`, `feat/`).
2. **Pull Requests:** Ningún cambio entra directamente a `main`; todo pasa por revisión de PR.
3. **Commits claros:** Usar mensajes descriptivos en los commits.
4. **Sincronización:** Hacer `git pull origin main` antes de iniciar una nueva tarea.

## Contribución Reto final rápido

Mi contribución: Para contribuir al proyecto, crea una nueva rama, realiza tus cambios,
haz un commit y posteriormente abre un Pull Request.

### 1. ¿Cuál es la diferencia entre `git add` y `git commit`?
* git add sirve para agregar los cambios que quiero guardar y git commit sirve para guardar esos cambios en el historial

### 2. ¿Cuál es la diferencia entre `git push` y `git pull`?
* git push es para subir mis cambios a GitHub y git pull es para traer los cambios de GitHub a mi computador

### 3. ¿Cuál es la diferencia entre un repositorio local y uno remoto?
* El repositorio local es el que tengo en mi computador y el remoto es el que está en GitHub. El local es donde trabajo y el remoto sirve para subir y compartir los cambios

### 4. ¿Qué problema resuelve una rama?
* Permite crear un borrador de trabajo para hacer tareas o probar cosas sin dañar el proyecto principal

### 5. ¿Qué diferencia existe entre `git merge` y `git rebase`?
* git merge une los cambios de una rama con otra, mientras que git rebase mueve los cambios de una rama para que queden después de los cambios de otra

### 6. ¿Por qué ocurre un conflicto?
* Ocurre cuando dos personas hacen cambios diferentes en la misma parte de un archivo y Git no sabe cuál de los dos cambios debe dejar

### 7. ¿Quién debe decidir cómo resolver un conflicto?
* Los desarrolladores involucrados en el cambio, poniéndose de acuerdo sobre qué código dejar

### 8. ¿Qué problema resuelve un Pull Request?
* Sirve para pedir que los cambios de una rama se revisen antes de unirlos con main

### 9. ¿Por qué es recomendable revisar un Pull Request antes de integrarlo?
* Porque así se pueden revisar los cambios, encontrar errores y verificar que todo esté bien antes de pasarlo a main

### 10. ¿Qué ventaja tiene trabajar en una rama en lugar de modificar directamente `main`?
* La ventaja es que puedo hacer cambios sin afectar main. Así puedo probar y corregir lo que sea necesario antes de unirlo al proyecto principal
